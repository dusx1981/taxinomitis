## `newLocalProjectModel` 测试套件

### 测试用例 1：`should update project expiry and labels after new models`

#### 步骤分解

1. **创建文本项目**

   ```http
   POST /api/classes/UNIQUECLASSID/students/userid/localprojects
   {
     type: "text",
     name: "update this project",
     labels: ["this"]
   }
   ```

   * 期望：201 CREATED
   * 保存项目 ID 与初始过期时间

2. **验证项目初始状态**

   * 从 DB 获取项目
   * 断言过期时间与创建时一致
   * 标签为 `["this"]`

3. **创建新模型**

   ```http
   POST /api/classes/UNIQUECLASSID/students/userid/localprojects/{projectid}/models
   {
     training: VALID_TEXT_TRAINING_DATA
   }
   ```

   * 使用训练数据（含意图 `"this"` 与 `"that"`）
   * 期望：201 CREATED
   * 验证返回结果：

     * `classifierid`
     * `credentialsid`
     * `status: "Training"`

4. **验证项目更新**

   * 再次查询项目
   * **断言1**：过期时间已延长
   * **断言2**：标签更新为 `["this", "that"]`

#### 关键逻辑

* **训练模型 → 更新项目元数据**

  * 延长过期时间（避免过早清理）
  * 从训练数据的 intents 自动更新标签

#### 训练数据示例

```js
VALID_TEXT_TRAINING_DATA = {
  intents: [
    { intent: "this", examples: [...] },
    { intent: "that", examples: [...] }
  ]
}
```

### 测试用例 2：`should reject requests for non-text projects`

#### 步骤

1. **尝试创建数字项目**

   ```http
   POST /api/classes/UNIQUECLASSID/students/userid/localprojects
   {
     type: "numbers",
     name: "numeric project",
     labels: ["this"]
   }
   ```

2. **验证拒绝**

   * 期望：400 BAD\_REQUEST
   * 错误信息：
     `"Local projects not supported for non-text projects"`

#### 设计意图

* **严格区分项目类型**
* 本地项目仅支持文本类型（text）
* 数字项目应使用单独的端点（如 `localnumbersprojects`）

---

## 核心业务逻辑

### 项目生命周期管理

1. **创建项目**：初始化标签 + 过期时间
2. **训练模型**：同步意图 → 标签，延长有效期
3. **更新机制**：保持项目与训练数据一致

### 错误处理策略

* **类型验证**：拒绝不支持的项目类型
* **数据完整性**：确保请求包含必要参数
* **权限控制**：验证用户/班级权限

---

✅ 这个测试套件保证了本地文本项目管理的正确性，特别是 **模型训练后项目元数据的自动更新机制**。
