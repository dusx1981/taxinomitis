# VS Code launch.json 配置深度解析

## 配置总览
- `Debug: app.ts (ts-node)`：直接运行**源码** `src/lib/app.ts`，通过 `ts-node/register` 实时编译（带类型检查）
- `Debug: app.ts (ts-node, transpile-only)`：运行**源码**但跳过类型检查，用于快速调试
- `Debug: dist/app.js (compiled)`：运行**编译产物** `dist/lib/app.js`，需配合 source map

---

## 配置1：Debug: app.ts (ts-node)
json
{
  "name": "Debug: app.ts (ts-node)",
  "type": "node",
  "request": "launch",
  "program": "${workspaceFolder}/src/lib/app.ts",
  "runtimeArgs": ["--require", "ts-node/register"],
  "env": {"NODE_ENV":"development", "TS_NODE_PROJECT":"${workspaceFolder}/tsconfig.json"}
}


### 核心机制
| 维度 | 说明 |
|------|------|
| **执行文件** | 直接执行 `src/lib/app.ts` 源文件 |
| **编译方式** | ts-node 内存编译（带完整类型检查） |
| **断点映射** | 直接在 `.ts` 文件设断点，自动映射 |
| **路径基准** | `__dirname` 指向 `src/lib` 目录 |
| **类型检查** | 严格检查，发现错误立即中断 |

### 典型问题
typescript
// 示例：路径解析差异
path.join(__dirname, '../../static') 
// 开发模式解析为 /src/lib/../../static
// 生产模式可能变为 /dist/lib/../../static

## 配置2：Debug: app.ts (transpile-only)
json
{
  "name": "Debug: app.ts (ts-node, transpile-only)",
  "type": "node",
  "request": "launch",
  "program": "${workspaceFolder}/src/lib/app.ts",
  "runtimeArgs": ["--require", "ts-node/register/transpile-only"]
}


### 关键特性
- 🚀 **编译速度**：比标准模式快 3-5 倍
- ⚠️ **类型安全**：完全跳过类型检查
- 🔥 **热修复**：临时绕过缺失类型声明
- 📉 **调试体验**：失去类型提示和错误预防

### 执行流程
mermaid
graph TD
    A[启动Node] --> B[挂载transpile-only]
    B --> C[按需编译TS→JS]
    C --> D[执行内存JS代码]

## 配置3：Debug: dist/app.js (compiled)
json
{
  "name": "Debug: dist/app.js (compiled)",
  "type": "node",
  "request": "launch",
  "program": "${workspaceFolder}/dist/lib/app.js",
  "sourceMaps": true,
  "outFiles": ["${workspaceFolder}/dist//*.js"]
}


### 生产环境模拟
1. **前置要求**：
   bash
   npm run build  # 生成dist和source map

2. **路径陷阱**：
   javascript
   // 生产环境常见问题
   fs.readFileSync(path.join(__dirname, 'config.json')) 
   // 开发时可能找到，生产环境因路径变化失效

3. **Source Map 验证**：
   - 检查 `dist` 目录是否包含 `.js.map` 文件
   - 验证映射准确性：在编译后的JS中打断点应能映射到TS

## 调试方案选型指南

| 场景 | 推荐方案 | 备选方案 | 风险提示 |
|------|----------|----------|----------|
| **日常开发** | ts-node标准模式 | - | 类型安全但启动慢 |
| **紧急调试** | transpile-only | - | 可能掩盖类型问题 |
| **构建验证** | dist模式 | - | 必须提前build |
| **路径敏感** | 统一使用 `process.cwd()` | 环境变量配置 | 避免硬编码路径 |

### 最佳实践建议
1. **路径处理标准化**：
   typescript
   // 推荐方案
   import path from 'path';
   const RESOURCE_PATH = path.resolve(process.cwd(), 'resources');

2. **环境隔离**：
   json
   // launch.json 片段
   "env": {
     "APP_MODE": "debug",
     "STATIC_ROOT": "${workspaceFolder}/static"
   }

3. **混合调试配置**：
   json
   {
     "compounds": [{
       "name": "Full Stack Debug",
       "configurations": ["Debug Node", "Debug Chrome"]
     }]
   }

## 常见问题排查速查表

| 症状 | 可能原因 | 解决方案 |
|------|----------|----------|
| 断点不生效 | source map 缺失 | 检查 `tsconfig.json` 的 `sourceMap` 配置 |
| 路径404 | `__dirname` 基准变化 | 改用 `process.cwd()` 基准路径 |
| 类型报错 | 缺少 `.d.ts` 声明 | 添加自定义类型声明文件 |
| 变量未定义 | 环境变量未注入 | 在 launch.json 中显式设置 `env` |
| 代码变更未生效 | 未启用文件监听 | 添加 `"restart": true` 配置 |

> 提示：生产环境问题建议始终使用 `dist` 模式调试，可最大限度复现线上行为
